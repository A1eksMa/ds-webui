# scripts/ — макросы офисного пакета (LibreOffice / AlterOffice)

Producer-конец цепочки: пользователь правит таблицу в офисном пакете, макрос
выгружает **колоночный JSON** с именем `<username>_<timestamp>.json` в папку,
которую мониторит [`ds-loader`](https://github.com/A1eksMa/ds-loader) → `ds load`.

`<username>` — системное имя пользователя. **Каждый пользователь — отдельный
источник `ds`**: нужен `sources/<username>/source.json` с его `key_label`.

| Файл | Назначение |
|---|---|
| `common.py` | общий код (разбор листа, имя файла, атомарная запись, лог) — не макрос |
| `export_full.py` | выгрузить **весь** активный лист (первичная загрузка источника) |
| `export_diff.py` | выгрузить **только изменения** из Excel-файла веб-морды ds-webui |

## Установка

1. Скопировать `common.py`, `export_full.py`, `export_diff.py` в
   `~/.config/<office>/<version>/user/Scripts/python/`.
2. В `common.py` задать:
   - **`INBOX_DIR`** — папку `update_dir` вашего `ds-loader`;
   - при необходимости — `LOG_DIR`.
3. Макросы: `Сервис → Макросы → Организовать макросы → Python →
   export_full / export_diff`.

## export_full.py

Активный лист (или `SHEET`): первая строка — заголовки (`label`), остальные —
данные, по строке на `id`. Колоночный JSON `{header: [values, ...]}`.

Исправления против исходного `export_json.py`:

- баг формата времени `%m` → `%M` (в имени были месяцы вместо минут);
- время в **UTC** (у `ds-loader` `filename_tz="utc"` по умолчанию);
- имя пользователя санитизируется (без `_` — `ds-loader` берёт за источник всё до
  первого `_`);
- запись в `INBOX_DIR`, а не рядом со скриптом;
- **атомарная** запись (`*.json.tmp` → `rename`) — `ds-loader` не увидит
  недописанный файл;
- данные считаются **до** открытия файла; пустой лист → файл не создаётся;
- ошибки идут в лог (`logging.exception`).

## export_diff.py

Для `.xls`, выгруженного веб-мордой ds-webui: две вкладки с одинаковыми данными —
`user` (правит пользователь) и `system` (эталон, не трогается).

Выгружается **только то, что пользователь создал или изменил**:

| Действие пользователя | В выгрузке |
|---|---|
| изменил значение существующей ячейки | да |
| добавил новый заголовок / показатель (`label`) | да — весь столбец (будущий пользовательский показатель) |
| добавил строку с новым `id` (нет в `system`) | **нет** — строка игнорируется |
| удалил строку / ничего не менял | нет |

Строки сопоставляются по ключевому столбцу (позиция 0 листа `user`, либо
`KEY_COLUMN`). Прочий разбор — как в `export_full`. Ничего не изменилось →
файл не создаётся. Вкладки ищутся по именам `user`/`system`, при их отсутствии —
по индексам 0 и 1.

## Известные ограничения

- **Формат Excel из ds-webui** — SpreadsheetML 2003 (Excel XML, расширение `.xls`).
  Обе вкладки (`user`, `system`) — настоящие листы с именами и в Microsoft Excel,
  и в LibreOffice / AlterOffice. Скрытие и защиту листа `system` последние могут
  не применять — тогда это два обычных листа (порядок `user`, `system`); макрос
  всё равно найдёт их по именам.
- Ячейки экспортируются как текст (`ss:Type="String"`), поэтому офисный пакет не
  приводит числовые строки к числам при открытии: `"99.00"` остаётся `"99.00"`,
  ключевой `"007"` не становится `7`. `export_diff` дополнительно сравнивает
  числа с терпимостью (`10` == `10.00`). Если пользователь вручную переключит
  формат ячейки на числовой и сохранит — значение может уехать в форме `95` /
  `95.5`; на сопоставление строк это не влияет, пока не тронут ключевой столбец.
- Колоночный формат `ds` не умеет «эту ячейку не трогать». В выгрузке
  `export_diff` для оставленной строки присутствуют все её изменённые/новые
  столбцы целиком; неизменённая ячейка в такой строке уедет в `ds` повторной
  записью того же значения. Оверхед ограничен (изменённые `id` × изменённые
  `label`).
- Пустая ячейка → `""` (как в `export_full`), не `null`/DELETE.
