# Changelog

Архивы в этой папке — рабочая версия сайта (без `docs/` и dev-инструментов), готовая к
распаковке и открытию. Имя архива содержит номер версии: `ds-webui-<version>.tar.gz`.
Он же — в `<meta name="version">` внутри `index.html`.

Для машины без git: скачать один архив вместо файлов по отдельности.

## Распаковка

```bash
mkdir -p /path/to/target/folder
tar -xzf ds-webui-<version>.tar.gz -C /path/to/target/folder
```

Внутри: `index.html`, `app.js`, `styles.css`, `presets.js`, `sample-data/`, `scripts/`,
`LICENSE`, `README.md`.

## Запуск

Открыть `index.html` в браузере (двойной клик). Ничего ставить не нужно, сеть не требуется.
Пока рядом нет каталога `data/` (вывод `ds-loader` / поллера), страница показывает
закоммиченный `sample-data/`.

`scripts/` — макросы офисного пакета для выгрузки листа в JSON под `ds-loader`
(см. `scripts/README.md`). `docs/contract.md` и `tools/gen_sample.py` в архив не входят —
они только в репозитории.

## 0.9.0a1 — `ds-webui-0.9.0a1.tar.gz`

Багфиксы поверх 0.8.0a1 — по итогам работы с реальными данными.

- **Условия в «Конструкторе» больше не обнуляют выборку.** Выпадающий список
  поля предлагал сырые столбцы, которых после резолва сущностей в строках нет —
  условие (`содержит` / `начинается с` / …) не проходило ни для одной строки,
  результат пустой. Теперь `condFields` = ровно итоговые столбцы (имена
  сущностей, с той же дедупликацией, что в `resolveEntities`; без сущностей —
  выбранные сырые столбцы). `applyConditions` вдобавок пропускает условие на
  несуществующее поле (устаревший пресет, переименованная сущность), а не
  режет по нему всю выборку — в «Конструкторе» селект поля показывает
  «поле…», нужно выбрать заново.
- **Тип «дата» понимает серийную дату Excel.** Даты из Excel-выгрузок хранятся
  целым числом (дни от 1899-12-30). `parseDate` в режиме `auto` теперь
  распознаёт 5–7-значное целое (опц. дробная часть суток) как серийную дату;
  не пересекается с unix-временем (9+ цифр). Явный `формат входа = excel` /
  `serial` — только этот разбор. Формула `(n − 25569) × 86 400 000`, диапазон
  1900-01-01 … 9999-12-31. Подсказка в карточке сущности обновлена.
- **Ширину столбца можно ужать уже текста заголовка.** `table-layout: fixed`
  при `width: max-content` всё равно мерил контент, и заголовок держал
  минимальную ширину столбца. Теперь `renderGrid` ставит таблице явную
  инлайновую ширину = сумма ширин столбцов (в CSS осталось `min-width: 100%`),
  при перетаскивании синхронно тянется и ширина таблицы. Поле фильтра в шапке
  (`min-width: 0`, `overflow: hidden`) тоже больше не держит ширину столбца.
- `app.js`, `styles.css`, `docs/contract.md`, `README`.

## 0.8.0a1 — `ds-webui-0.8.0a1.tar.gz`

Юзабилити «Конструктора» и «Таблицы»: сворачивание тяжёлых блоков, ручная
ширина столбцов, перенос длинного текста, полноэкранный режим таблицы,
выгрузка в Excel с пропорциями ширины и переносом.

- **Конструктор → фолдинг источников.** У каждого источника кнопка `+`/`−`
  сворачивает вертикальный список показателей (по умолчанию свёрнут; в шапке —
  счётчик `показателей: N из M`). При десятке источников по сотне полей страница
  больше не разъезжается по высоте.
- **Конструктор → карточка «Сущность» перекомпонована.** Первая строка — только
  «Наименование» + группа пиктограмм (`↑` `↓` `✕`) в правом верхнем углу. Ниже —
  отдельными строками с подписями: «Способ расчёта», «Тип данных», «Источник
  расчёта» (у «коллизии» строка входов `поле · вес · ↑ · ↓ · ✕` не изменилась).
  Весь блок «Сущности» сворачивается кнопкой у заголовка.
- **Конструктор → убран подблок формата** (ширина / выравнивание / кегль):
  ручная настройка в карточке признана неудачной. Значения работают по дефолту;
  `format.*` из загруженного пресета по-прежнему применяются.
- **Таблица → ручная ширина столбца.** Тянешь правую границу ячейки заголовка;
  двойной клик по границе — сброс к дефолту (150 px). Хранится в пресете
  (`view.column_widths`). Таблица переведена на `table-layout: fixed`.
- **Таблица → перенос длинного текста.** Значение-«простыня» (1000+ символов)
  больше не растягивает столбец в одну строку и не утаскивает остальные за край
  видимости — текст переносится по ширине столбца (`overflow-wrap: anywhere`).
- **Таблица → режим «во всю ширину окна».** Флажок на панели: грид вырывается
  из колонки контента (макс. 1200 px) во всю ширину окна — для широкого окна на
  двух мониторах. Хранится в `localStorage` (свойство рабочего места, в пресет
  не идёт). Заодно починено восстановление поля «Автор» из `localStorage`
  (первый `render` затирал ключ раньше, чем boot успевал прочитать).
- **Выгрузка в Excel → ширина столбцов и перенос.** `<Column ss:Width>` по
  пропорциям со страницы (px → пункты ×0.75, зажим `[24; 720]`); стиль ячеек с
  `WrapText` и выравниванием по верху, жирная шапка. CSV не изменён; формат
  остаётся SpreadsheetML 2003.
- `app.js`, `styles.css`, `docs/contract.md` (`view.column_widths`, режим
  ширины), `README`.

## 0.7.0a1 — `ds-webui-0.7.0a1.tar.gz`

Выгрузка в Excel — настоящие две вкладки (как и было описано в `README`).

- Кнопка «Выгрузить в Excel» теперь пишет **SpreadsheetML 2003** (Excel XML,
  расширение `.xls`) вместо legacy Excel-HTML с MSO-островом. Прежняя разметка
  двух листов не давала: один файл с двумя `<table>` и островом без
  `WorksheetSource` открывался одним листом (данные задваивались), имена/скрытие/
  защита игнорировались.
- Два настоящих `<Worksheet>`: `user` (`<Selected/>`, видимый) и `system`
  (`ss:Protected="1"`, `<Visible>SheetHidden</Visible>`, `ProtectContents/Objects/
  Scenarios`, пустой пароль). Именованные вкладки открывают и Microsoft Excel, и
  LibreOffice / AlterOffice; скрытие и защиту листа последние могут не применять —
  тогда это два обычных листа `user` / `system`.
- Ячейки — `ss:Type="String"`: office-пакет не приводит `007` / `99.00` к числу
  при открытии (снимает риск для ключевого столбца в `scripts/export_diff.py`).
  Пустая ячейка — `<Cell/>` (позиция столбца сохраняется).
- `app.js`: `xlsTable` / `xlsSheetMeta` → `xlsRow` / `xlsWorksheet` / `toXlsWorkbook`.
  MIME и имя файла (`<author>_<ts>.xls`) не изменились. CSV не затронут.
- `README`, `scripts/README.md`, `scripts/export_diff.py`, `scripts/common.py` —
  описание формата приведено в соответствие.

## 0.6.0a1 — `ds-webui-0.6.0a1.tar.gz`

Слой формирования сущностей в «Конструкторе» — браузерный Level 2.

- Новый шаг **«Сущности (столбцы таблицы)»**: из выбранных полей собираются итоговые
  столбцы. Три вида (`from.kind`):
  - `field` — поле как есть;
  - `resolve` — разрешение коллизии: несколько входов, **веса доверия задаёт пользователь**
    (в пресете), победитель — наибольший вес среди присутствующих; при равных весах — по
    порядку входов; `null_wins` — `null` (DELETE) из весомого источника побеждает. Тайбрейк
    по `dt`/`cnt` не поддержан (их нет в `ds get`);
  - `derived` — производная: `sum`/`avg`/`min`/`max`/`concat`/`first_nonempty`/`count_nonempty`.
- Каждая сущность: `name` (алиас/заголовок), `type` (`text`/`number`/`date`/`bool` — задаёт
  парсинг строки; промах → сырой текст с подсветкой `unparsed`, в сортировке — в конце),
  `format` (`width`/`align`/`font_size`), `parse` (формат даты, токены bool, десятичный
  разделитель). Порядок сущностей = порядок столбцов (стрелки ↑/↓).
- Пресет: `view.entities: [ … ]`. Пусто → неявные 1:1-сущности (обратная совместимость).
  Условия `view.conditions` теперь фильтруют столбцы-сущности.
- Конвейер `buildDataset`: `joinSources` → `resolveEntities` → `parseTypes` (`__k` —
  типизированный ключ сортировки, `__u` — промах) → `applyConditions`. Сортировка на
  «Таблице» — по `__k` (даты хронологически, числа численно). `<colgroup>` для ширин.
- `app.js` (parseNum/parseDate/formatDate/parseBool/typeCell/resolveCell/resolveEntities/
  parseTypes/normalizeEntities, редьюсер `preset/*Entity*`, секция и `entityRow` в
  «Конструкторе», `renderGrid`/`cellNode`/`applySort`), `styles.css`, `presets.js`,
  `docs/contract.md`, `README`.
- Гарнес `entity_test.js`: 49/49.

## 0.5.0a1 — `ds-webui-0.5.0a1.tar.gz`

Расширенный фильтр и сортировка на странице «Таблица».

- **Расширенный фильтр** — кнопка рядом с ⚙ разворачивает панель над таблицей.
  Строки `[И/ИЛИ] · поле · оператор · значение` (операторы те же, что в условиях
  «Конструктора», включая `in`/`not_in` со вставкой списка). Несколько условий на один
  столбец. Связка на каждой строке; `И` приоритетнее `ИЛИ` (`a И b ИЛИ c` = `(a И b) ИЛИ c`).
  Применяется **после** условий «Конструктора», но **до** быстрых фильтров в шапке.
  «Сбросить всё» / удаление построчно. Транзиентный: не в пресете, не в `localStorage`,
  сбрасывается при пересборке из «Конструктора».
- **Сортировка** по клику на заголовок столбца: по возр. → по убыв. → без. Одна колонка,
  числа — как числа, пустые всегда в конце. Тоже транзиентная.
- Конвейер «Таблицы»: built → расширенный фильтр → быстрые фильтры → сортировка → группировка.
  Выгрузка в Excel/CSV учитывает все слои и сортировку.
- `app.js` (applyAdvanced / evalRowGroups / applySort / renderAdvFilter, общие `opSelect` /
  `valueControl`), `styles.css`, `docs/contract.md`, `README`.

## 0.4.0a1 — `ds-webui-0.4.0a1.tar.gz`

Условие «в списке» + вставка списка из буфера обмена.

- Операторы `in` («в списке») и `not_in` («не в списке») в условиях выборки: строка
  проходит, если значение поля входит (не входит) в заданный список. Регистронезависимо.
- Для этих операторов значение — многострочное поле (`textarea`): по одному значению на
  строку либо через `,` `;` таб. Рядом — кнопка **«Вставить из буфера»**
  (`navigator.clipboard.readText()`; при отказе — подсказка вставить `Ctrl+V` вручную) и
  счётчик распознанных значений. Типовой сценарий — готовый список идентификаторов.
- Хранится в пресете там же — `view.conditions[].value` (как текст списка). Пустой список →
  условие неактивно.
- `app.js` (parseList / matchCondition in|not_in / pasteFromClipboard / conditionRow),
  `styles.css`, `docs/contract.md`, `README`.

## 0.3.0a1 — `ds-webui-0.3.0a1.tar.gz`

Условия выборки в «Конструкторе» вместо подстрочных базовых фильтров.

- Блок **«Условия»**: строки `поле · оператор · значение`, добавляются кнопкой `+ условие`,
  количество любое (в т.ч. ноль), каждая удаляется `✕`. Поле — из уже выбранных на первом
  шаге показателей.
- Операторы: `contains`, `not_contains`, `eq`, `ne`, `starts`, `ends`, `gt`, `gte`, `lt`,
  `lte` (числовое сравнение; пустая ячейка не подходит), `empty`, `not_empty` (значение не
  нужно, поле ввода блокируется). Строковые — без учёта регистра.
- Применяются **при построении датасета**, последовательно (И) — на «Таблицу» уходит уже
  суженный массив. Пофакторные фильтры в шапке таблицы — поверх, как и раньше.
- Хранятся в пресете как `view.conditions: [{field, op, value}]`. Прежнее
  `view.column_filters` при загрузке пресета мигрирует в `conditions` (оператор `contains`).
- `app.js` (matchCondition / applyConditions / normalizeConditions / reducer / конструктор),
  `styles.css`, `presets.js`, `docs/contract.md`.

## 0.2.0a1 — `ds-webui-0.2.0a1.tar.gz`

Пофакторные фильтры в шапке таблицы — применение по требованию, а не посимвольно.

- Ввод в поле фильтра столбца больше не фильтрует на каждый символ. Условие набирается
  целиком и применяется по `Enter` или по кнопке-воронке, добавленной в конце поля справа.
  `Esc` — отменить несохранённый ввод. Пустое поле + `Enter` — снять фильтр столбца.
- Пока ввод не применён, поле подсвечено (класс `dirty`) — видно, что есть неприменённое
  изменение. После применения фокус остаётся в поле — можно уточнять.
- Только `app.js` (`renderGrid`) и `styles.css`; поведение датасета и контракт не менялись.

## 0.1.0a1 — `ds-webui-0.1.0a1.tar.gz`

Первая альфа. Рабочая вьюшка поверх файлового контракта `ds` → `ds-webui`.

- Две страницы: **Таблица** (широкая таблица, пофакторные фильтры, группировка со
  сворачиванием, «скрыть пустые колонки», экспорт в `.xls` и `CSV` — всё клиентски) и
  **Конструктор выборки** (выбор источников/показателей, срез `as_of`, межисточниковый
  LEFT JOIN, подстрочные фильтры, пресеты).
- Полностью serverless: статические `index.html` + `.js`, работает как `file://`, без сети.
  Манифест грузится инъекцией `<script>` с fallback `data/` → `sample-data/`.
- `presets.js` — базовый пресет; последний использованный запоминается в `localStorage`.
- `sample-data/` — настоящий вывод `ds get` из двух источников (один свежий, один
  намеренно устаревший — чтобы был виден бейдж «пересобрать»).
- `scripts/` — макросы офисного пакета (`export_full.py`, `export_diff.py`, `common.py`):
  выгрузка листа целиком или только правок в JSON по неймингу `ds-loader`.
- Файловый контракт — `docs/contract.md`. Данные во вьюшку кладёт стадия `publish`
  загрузчика `ds-loader` (>= 0.4.0a1).
- Не реализовано: drag-and-drop пресета, вычисляемые/семантические показатели, поллер
  (роль поллера сейчас исполняет `ds-loader`).
