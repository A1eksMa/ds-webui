# Changelog

Архивы в этой папке — рабочая версия сайта (без `docs/` и dev-инструментов), готовая к
распаковке и открытию. Имя архива содержит номер версии: `ds-webui-<version>.tar.gz`.
Он же — в `<meta name="version">` внутри `index.html`.

Для машины без git: скачать один архив вместо файлов по отдельности.

**Два варианта архива на одну и ту же версию** (начиная с 0.28.0a1) — `ds-webui`'s core
один и тот же, различие только в наличии опционального конвертера `.xlsx`
([`ds-webui-import`](https://github.com/A1eksMa/ds-webui-import), подключается как git
submodule, каталог `import/`):

- `ds-webui-<version>.tar.gz` — **lite**, без `import/`: ни кнопки «Импорт» на
  «Настройках», ни единой внешней зависимости (та же минималистичная версия, что и раньше).
- `ds-webui-<version>-with-import.tar.gz` — **full**, с распакованным `import/` внутри:
  кнопка «Импорт из Excel» появляется.

Выбор не влияет на номер версии — обе собраны из одного и того же состояния репозитория,
отличается только присутствие опционального каталога `import/`.

## Распаковка

```bash
mkdir -p /path/to/target/folder
tar -xzf ds-webui-<version>[-with-import].tar.gz -C /path/to/target/folder
```

Внутри (lite): `index.html`, модули приложения (`util.js`, `effects.js`, `dataset.js`,
`entities.js`, `export.js`, `store.js`, `view-common.js`, `view-build.js`, `view-entities.js`,
`view-table.js`, `main.js`), `styles.css`, `sample-data/` (включая пресет по умолчанию
`base.js`), `scripts/`, `LICENSE`, `README.md`. В `-with-import` — дополнительно каталог
`import/` (`import.js`, `vendor/xlsx.full.min.js`, `vendor/SHEETJS-LICENSE`, `LICENSE`,
`README.md` этого отдельного репозитория — подробности и его собственный changelog там же,
[`ds-webui-import/releases/README.md`](https://github.com/A1eksMa/ds-webui-import/blob/main/releases/README.md)).

## Запуск

Открыть `index.html` в браузере (двойной клик). Ничего ставить не нужно, сеть не требуется.
Пока рядом нет каталога `data/` (вывод `ds-loader` / поллера), страница показывает
закоммиченный `sample-data/`.

`scripts/` — макросы офисного пакета для выгрузки листа в JSON под `ds-loader`
(см. `scripts/README.md`). `docs/contract.md` и `tools/gen_sample.py` в архив не входят —
они только в репозитории.

## 0.28.0a1 — `ds-webui-0.28.0a1.tar.gz` / `ds-webui-0.28.0a1-with-import.tar.gz`

Безусловный переход на ленивый columnar-формат источников + поддержка нескольких файлов
манифеста + опциональный конвертер `.xlsx`.

- **Ленивый формат `data/<Source>.js`** (требует `ds-loader` 0.9.0a1+, вместе с которым и
  выпущено) — каждый показатель (+ ключ) оборачивается в свою функцию; `ds-webui` вызывает
  только геттеры реально нужных показателей, остальные не парсятся/не аллоцируются браузером
  (ленивая компиляция V8). Решает проблему источников с сотней показателей, из которых
  нужен один-два. Старый построчный формат убран без обратной совместимости.
- **`manifest.imports.js`** — опциональный индекс произвольного числа файлов-фрагментов
  манифеста, объединяемых с основным `manifest.js` на чтении (явная ошибка при совпадении
  имён источников). На «Настройках» — поле «Каталог данных» + кнопка «Обновить манифест»
  (перечитать манифест без перезагрузки страницы, или переключиться на другой каталог).
- **Кнопка «Импорт из Excel»** на «Настройках» — только если подключён (как git submodule)
  отдельный открытый репозиторий [`ds-webui-import`](https://github.com/A1eksMa/ds-webui-import):
  разбирает `.xlsx` в тот же ленивый формат + фрагмент манифеста, без единой новой
  зависимости в lite-сборке. См. "Два варианта архива" выше.
- `store.js` (+`mergeManifests`, `manifestError`), `effects.js` (`loadManifest`,
  `loadManifestFragments`), `main.js` (bootstrap вынесен из `index.html`), `view-build.js`,
  `docs/contract.md`; 107 тестов (было 100), плюс оба DOM-смоук-теста.

## 0.27.0a1 — `ds-webui-0.27.0a1.tar.gz`

Четыре доработки quick-пиктограмм поиска/фильтра/сортировки в шапке таблицы (0.24.0a1) —
по итогам реального использования.

- **Фиксированная ширина поля ввода** — больше не сжимается вместе с узкой колонкой
  (раньше при маленькой ширине столбца в поле иногда было невозможно позиционировать
  курсор). Панель — оверлей поверх строк таблицы, может перекрывать соседние заголовки
  при узкой колонке — это нормально.
- **Новое поведение открытия/закрытия**: появляется по клику на пиктограмму; закрывается
  по `Enter`, по клику вне панели (в любом месте страницы) или по повторному клику на
  пиктограмму. Раньше закрывалось только повторным кликом.
- **Клик по значению из выпадающего списка теперь подставляется в поле** — раньше для
  поиска (у которого, в отличие от фильтра, нет «применённого» состояния в `state.adv`)
  поле после выбора значения из списка визуально обнулялось.
- **Пиктограмма сортировки заменена на воронку** (тот же визуальный язык, что у фильтра):
  без сортировки — воронка-контур; по возрастанию — перевёрнутая воронка со стрелкой
  вверх; по убыванию — обычная воронка со стрелкой вниз.
- `store.js` (+`quick/closeAll`), `view-common.js`, `view-table.js`, `styles.css`;
  100 тестов (было 99), плюс оба DOM-смоук-теста (`tests/smoke/`).

## 0.25.0a1 — `ds-webui-0.25.0a1.tar.gz`

Две связанные проблемы, обе вокруг хранения настроек: сохранённый пресет был общим на
весь file://-источник (нельзя было держать разные пресеты в разных вкладках), и при краше
вкладки от нехватки памяти на большом пресете он применялся заново при каждой
перезагрузке — цикл перезапуска без выхода.

- **`effects.js::storage` переведён с `localStorage` на `sessionStorage`** — сохранённый
  пресет и `quickValuesLimit` теперь привязаны к конкретной вкладке, а не общие на весь
  источник. Открытые одновременно вкладки с разными пресетами больше не перетирают
  настройки друг друга; новая вкладка всегда начинает с чистого состояния.
- **Watchdog-защита от цикла перезапуска на нехватке памяти** (`main.js`) — флаг
  `renderWatchdog` выставляется перед началом сборки (`buildDataset`) и перед каждой
  (пере)отрисовкой «Таблицы» (сортировка/фильтр/группировка тоже перестраивают DOM целиком,
  тот же риск), снимается только после подтверждённого прохода браузера по layout/paint
  (двойной `requestAnimationFrame`). Если флаг найден выставленным на старте той же вкладки
  — прошлый `render()` не дошёл до подтверждённого кадра (типичный симптом — браузеру не
  хватило памяти и вкладка перезапустилась). В этом случае вместо сохранённого пресета
  применяется гарантированно пустой (не `basePreset()` — `data/base.js` сам может оказаться
  тем же большим набором), с пояснением на странице «Конструктор»; сохранённый пресет
  остаётся в `sessionStorage` нетронутым — его можно открыть вручную.
- Докстрапнутый баг, найденный при добавлении теста на этот сценарий: восстановление
  молча затирало сохранённый пресет пустым (обычный автосейв `render()` срабатывал на
  промежуточных рендерах восстановления) — исправлено явным восстановлением исходного
  значения после dispatch-цепочки восстановления.
- `tests/smoke/dom-smoke.js` — новый сценарий `--simulate-crash` (предсеивает
  `renderWatchdog`+сохранённый пресет, проверяет восстановление и сохранность пресета).
- 99 тестов (как в 0.24.0a1 — сценарий `--simulate-crash` не под `node --test`, см.
  `tests/smoke/README.md`).

## 0.24.0a1 — `ds-webui-0.24.0a1.tar.gz`

Расширенный фильтр получает полноценную сортировку; заголовок таблицы — три пиктограммы
(поиск/фильтр/сортировка) вместо всегда открытого поля фильтра.

- **Сортировка в «Расширенном фильтре»** — новая секция «Отсортировать»: несколько
  уровней (`поле` + направление), порядок строк = приоритет (`ORDER BY поле1, поле2, ...`),
  тот же UI, что у группировки (`+`/↑/↓/✕). Попутно переименована сама секция группировки:
  она была озаглавлена «Отсортировать» (стойкий мисклейбл с тех пор, как группировка жила
  там одна) — теперь «Сгруппировать». `state.sort` → `state.sortBy` (массив), `applySort`
  — однопроходный многоуровневый компаратор. Сортировка внутри группы держится
  автоматически: `renderGrid` сортирует строки до группировки, а группировка —
  стабильное партиционирование.
- **Три пиктограммы под именем столбца** вместо всегда открытого текстового фильтра:
  поиск, фильтр, сортировка. Поиск — переход к следующей строке ниже, содержащей текст (с
  оборотом в начало, раскрывает свёрнутые группы по дороге) — навигация, не фильтрация, без
  аналога в расширенной панели. Фильтр и сортировка пиктограмм **читают/пишут то же самое
  состояние**, что расширенная панель: клик по пиктограмме-воронке добавляет/правит
  `содержит`-условие в общем списке условий (`conj: "and"`, не трогая остальные); клик по
  пиктограмме сортировки крутит этот столбец в общем списке уровней (нет записи → по
  возр. → по убыв. → без). Поля поиска и фильтра — один и тот же визуальный компонент,
  включая общий выпадающий список первых N уникальных значений столбца (в порядке строк,
  не по частоте — ради экономии на столбцах с почти уникальными значениями) с
  настраиваемым N («Показать N» под списком, `N=0` выключает список).
- `state.tableFilters` убран — быстрый текстовый фильтр переехал внутрь `state.adv`
  (одно и то же условие теперь видно и в пиктограмме, и в расширенной панели).
- 99 тестов (было 76).

## 0.22.0a1 — `ds-webui-0.22.0a1.tar.gz`

Догоняет `manifest.js`'s `label_types` (аддитивное поле с `ds-loader` 0.5.0a1) — до этого
релиза оно долетало до браузера, но нигде не читалось.

- **Дефолтный тип нового индикатора — из `label_types` манифеста**, а не всегда `"text"`.
  Задевает все три точки создания индикатора из сырого поля:
  - `entities.js::implicitEntities` — неявные индикаторы, когда пресет ещё пустой
    (`main.js::buildDataset` теперь считает `{колонка: type}` через новую
    `columnTypesFor` и передаёт её вторым аргументом);
  - «+ индикатор» (`store.js`, `preset/addEntity`);
  - «+ показатель источника» (`store.js`, `preset/addFieldEntity`).
  Показатель без записи в манифесте (ещё не опубликован источником, старый манифест без
  поля вовсе) — по-прежнему `"text"`, как раньше. Пользователю больше не нужно вручную
  выставлять «число»/«дата» на каждый показатель, если источник уже объявил тип в своём
  `source.json`.
  Новая `entities.js::columnTypesFor(sourceLabels, manifestSources)` — чистая функция,
  та же схема квалификации имён («Источник.показатель» при >1 источника), что уже
  использует `presetColumns`/`joinSources`, иначе типы не совпали бы со столбцами после
  JOIN. `columnType(preset, manifestSources, column)` — то же самое по одной колонке, для
  редьюсеров `store.js` (они видят только пресет, ещё без построенного датасета).
  Намеренно не трогает `preset/updateEntity` — смена поля у уже существующего индикатора
  может быть осознанным выбором пользователя (например, трактовать числовое поле как
  текст), автосброс типа туда не добавлен.
- **`docs/contract.md`** теперь документирует `label_types` в примере `manifest.js` (до
  этого релиза поле не было формализовано как часть контракта, хотя `ds-loader` отдаёт
  его с 0.5.0a1).
- **`tools/gen_sample.py`** (эталонная реализация шага поллера) и `sample-data/manifest.js`
  приведены в соответствие — `source.json` для сэмплов теперь объявляет `labels[].type`
  (ERP: `price`/`stock` → `number`; CRM: `email`/`phone`/`status` → `text`), манифест несёт
  `label_types`. `CRM.js`/`ERP.js`/`base.js` не изменились — только `manifest.js`.
- 70 тестов (было 60) — новые для `implicitEntities`/`columnTypesFor`/`columnType` и для
  `preset/addEntity`/`preset/addFieldEntity` с заполненным манифестом.

## 0.21.0a1 — `ds-webui-0.21.0a1.tar.gz`

Серьёзная переработка пайплайна сборки: «Настройки» и «Индикаторы» перестают быть
взаимоисключающими способами задать выборку — теперь последовательные шаги, как
`FROM`/`WHERE` → `SELECT` в SQL.

- **Связки между источниками — присоединение к уже накопленному множеству, как SQL
  JOIN**, а не произвольная пара: связка привязана к каждому источнику, кроме первого
  (базового), появляется/исчезает автоматически при отметке/снятии источника; «слева»
  можно выбрать только источник, уже вошедший в выборку раньше. Раньше «+ связка»
  создавала независимую пару из полного списка источников — при 3+ источниках это не
  отражало реальную сборку и позволяло оставить источник без связки (тогда подставлялся
  неявный дефолт «ключ=ключ» с базовым).
- **Условия отбора разделены на два независимых прохода**: `view.conditions` на
  «Настройках» — по сырым полям источников, сразу после JOIN; `view.entityConditions`
  (новое) на «Индикаторах» — по именам индикаторов, после их расчёта. Раньше был один
  список, целиком переключавшийся на имена сущностей, как только появлялся хоть один
  индикатор — приходилось постоянно прыгать между вкладками, чтобы вернуть доступ к
  сырым полям.
- **«Индикаторы»: раздельные «+ индикатор» и «+ показатель источника»** — вторая кнопка
  добавляет поле как есть без типизации/переименования, по одной на каждое выбранное
  поле, без блокировки повторного добавления (то же поле можно вывести как есть и
  одновременно использовать как вход производного индикатора). Кнопка «+ все выбранные
  поля (1:1)» убрана как избыточная.
- **Индикатор можно скрыть из таблицы** (`hidden`) — продолжает считаться и доступен
  условиям `entityConditions`, но не выводится в таблицу/экспорт/расширенный фильтр.
  Закрывает сценарий «нужен для расчёта/фильтра, но не для показа».
- При выборе источника по умолчанию включается **только ключевой показатель**, а не все
  показатели сразу — у источников бывает по сотне полей, снимать вручную лишние было
  неудобно.
- **Сохранённый в `localStorage` пресет проверяется на совместимость** с текущими
