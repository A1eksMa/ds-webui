# Файловый контракт `ds` → `ds-webui`

Единственная связь между проектами. `ds-webui` полагается только на формат ниже, никогда —
на схему БД `ds`.

Генератор — `ds get` (потребляет пресет, см. [preset](#пресет)). Файлы кладутся в `data/`
рядом с `index.html`. Каждый — валидный JS, дописывающий в глобал; порядок загрузки не важен;
повторная загрузка перезаписывает слот источника.

## `data/manifest.js`

Маленький, читается страницей всегда — чтобы показать доступные источники и их колонки
**без загрузки самих данных**.

```js
window.DS_MANIFEST = {
  generated_at: 1717372800,          // когда перестроен манифест (unix, сек)
  db_max_cnt: 84213,                 // максимальный cnt в БД на момент генерации — для детекта лага
  sources: [
    {
      name: "CRM",
      file: "CRM.js",
      key: "customer_id",            // ключевой показатель источника (по нему LEFT JOIN внутри источника)
      as_of: 1717200000,             // дата среза, на которую свёрнуто состояние
      generated_at: 1717372800,      // когда сгенерирован этот файл источника
      gen_max_cnt: 84010,            // cnt, до которого учтены данные (для бейджа "файл отстаёт от БД")
      rows: 4200,
      labels: ["email", "phone", "status"]   // колонки в файле (выбранные пресетом + вынужденные)
    }
  ]
};
```

## `data/<Source>.js`

```js
window.DS = window.DS || { sources: {} };
window.DS.sources["CRM"] = {
  meta: {
    name: "CRM",
    key: "customer_id",
    as_of: 1717200000,
    generated_at: 1717372800
  },
  data: [
    { customer_id: "101", email: "alice@example.com", phone: "+7-900-000-0001", status: "active" },
    { customer_id: "102", email: "bob@example.com",   phone: null,              status: "active" },
    { customer_id: "103", email: "carol@example.com", status: "blocked" }
  ]
};
```

Правила:

- **Широкая таблица:** одна строка на `id`, ключи объекта — `key` источника + выбранные показатели.
- **Значения — строки** (типизация не входит в `ds`, см. его `docs/explanation/data-model.md`).
- **`null`** у ключа = значение удалено в источнике (операция `DELETE`).
- **Отсутствующий ключ** в объекте строки = показателя для этого объекта не было ни в одной
  транзакции. Это не то же самое, что `null`.
- В файл всегда включаются: `key` источника и поля, по которым идёт межисточниковый LEFT JOIN
  (даже если пользователь не выбрал их для отображения) — иначе join в браузере не по чему делать.

## Пресет

Продукт «Конструктора выборки», вход для `ds get`. Формат — черновой, будет уточняться:

```json
{
  "name": "base",
  "as_of": null,
  "sources": {
    "CRM": { "labels": ["email", "phone", "status"], "filters": {} },
    "ERP": { "labels": ["price", "stock"], "filters": {} }
  },
  "joins": [
    { "left": "CRM", "left_field": "customer_id", "right": "ERP", "right_field": "client_ref" }
  ]
}
```

- `as_of: null` → `ds get` берёт текущую дату/время.
- `filters` — простые пофакторные фильтры, проталкиваемые в `ds get` (условия поверх свёртки).
  Сложная фильтрация и сворачивание — уже в браузере, на странице таблицы.
- Базовый пресет коммитится в `presets.js`; пользовательские — скачиваются/загружаются файлом.

## Детект устаревания

Страница сравнивает `manifest.db_max_cnt` с `source.gen_max_cnt`: если файл источника отстаёт
от БД — показать бейдж «пересобрать». Перегенерацию делает поллер (по базовому пресету) или
пользователь вручную (`ds get --preset ...`).
