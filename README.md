# ds-webui

Веб-интерфейс для просмотра и выборки данных из [`ds`](https://github.com/A1eksMa/ds) —
движка хранения историзированных данных.

Отдельный проект. С `ds` связан **только через файловый контракт** (см. ниже) — не читает
базу SQLite напрямую, не импортирует код ядра.

## Ограничения

- **Без серверов.** Только статические `index.html` + `.js`, открываются как `file://`.
  Сетевые взаимодействия запрещены абсолютно.
- Из-за `file://` данные не забираются через `fetch()` — они приходят как `.js`-файлы,
  дописывающие в глобал `window.DS`, и подгружаются динамической инъекцией `<script>`.
- Всё работает клиентски поверх загруженного в память снапшота. «Живого» запроса к базе нет.

## Запуск

Скачать репозиторий и открыть **`index.html`** в браузере (двойной клик). Ничего ставить не
нужно. Если каталога `data/` нет, страница подхватывает закоммиченный [`sample-data/`](sample-data/)
(настоящий вывод `ds get` из двух источников).

В боевом режиме поллер кладёт свежие файлы в `data/` рядом с `index.html` — страница
предпочитает его, `sample-data/` остаётся fallback'ом.

## Что происходит при открытии

Страница сразу применяет **пресет по умолчанию** (последний использованный из
`localStorage`, иначе — `base.js` рядом с данными; подробнее в «Контракт с `ds`») и
открывает **Таблицу**. Конструктор не мелькает.
Если построить не удалось (нет данных / нет источника) — открывается Конструктор с ошибкой.

## Две страницы

1. **Таблица** (стартовая). Под заголовком — имя пресета, источники и **срез (`as_of`)**,
   с которым сделана именно эта сборка (текст «текущий момент», если срез не задан) —
   значение зафиксировано на момент нажатия «Применить», не следует за полем `as_of` в
   «Конструкторе», если там что-то поменяли, но не пересобрали. Широкая HTML-таблица
   (колонки при нескольких источниках квалифицируются `Источник.показатель`). Три слоя
   фильтрации, друг поверх друга:
   условия из «Конструктора» (при построении) → **расширенный фильтр** → быстрые
   пофакторные фильтры в шапке. **Расширенный фильтр** — кнопка рядом с ⚙ разворачивает
   панель над таблицей со строками `И/ИЛИ · поле · оператор · значение` (те же операторы,
   что в настройках; можно несколько условий на столбец; `И` приоритетнее `ИЛИ`).
   Он временный: «Сбросить всё» возвращает выборку, в пресет не пишется, при перезагрузке
   пуст. **Быстрые фильтры** в шапке — по одному подстрочному на столбец, применяются по
   `Enter` или кнопкой-воронкой (`Esc` — отменить ввод). **Сортировка** — клик по заголовку
   столбца (по возр. → по убыв. → без); числа сравниваются как числа, пустые — в конце.
   **Ширина столбца** — тянешь правую границу ячейки заголовка (двойной клик по границе —
   сброс к дефолту); значение хранится в пресете (`view.column_widths`). Таблица —
   `table-layout: fixed`: длинное значение (блок текста в 1000+ символов) **переносится
   по ширине столбца**, а не растягивает его; заголовок столбца тоже переносится по
   словам (высота шапки растёт под самый длинный).
   Флажок **«во всю ширину окна»** — таблица вырывается из колонки контента (макс. 1200 px)
   и занимает всю ширину окна браузера: полезно, когда столбцов много и окно растянуто на
   два монитора. Запоминается в `localStorage` (свойство рабочего места, в пресет не идёт).
   Область таблицы ограничена по высоте (~70vh) и сама скроллится по обеим осям (шапка
   столбцов липнет к её верху) — как замороженные области в Excel.
   **Многоуровневая группировка** (в панели «Расширенный фильтр», рядом с условиями) —
   несколько полей применяются вложенно по порядку (сначала первое, внутри каждой
   группы — второе, и так далее), каждый узел сворачивается/разворачивается отдельно,
   «скрыть пустые колонки», выгрузка в Excel (`.xls`) и `CSV` — всё клиентски, без
   библиотек. `∅` в ячейке — удалённое значение (`DELETE`), пустая ячейка — показателя
   для объекта не было. Справа сверху — **⚙ Настройки**.

   Файл Excel — две вкладки с одинаковыми данными: `user` (видимая, активная) и
   `system` (скрытая и защищённая от изменений, пароль пустой). Формат — SpreadsheetML
   2003 (Excel XML, расширение `.xls`), без библиотек: настольный Microsoft Excel
   открывает обе вкладки, применяя имена, скрытие и защиту; LibreOffice / AlterOffice
   имена вкладок читают, скрытие и защиту листа могут игнорировать — тогда это два
   обычных листа `user` / `system`. Ячейки выгружаются текстом, поэтому `007` и
   `99.00` не превращаются в числа при открытии. Ширина столбцов в файле —
   пропорциональна заданной на странице (px → пункты), шапка жирная, во всех
   ячейках включён перенос по словам с выравниванием по верху (длинный текст
   складывается по ширине столбца, а не тянется одной строкой).

   Имя файла (и Excel, и CSV) — по неймингу файлов, которые мониторит `ds-loader`:
   `<автор>_YYYY-MM-DD_HH-MM-SS_<микросекунды>.<ext>`. В роли «источника» — поле **Пользователь**
   на панели таблицы (браузер системное имя ОС не отдаёт; пусто → `user`). Значение
   запоминается в `localStorage`.
2. **Конструктор выборки** (по кнопке ⚙ Настройки). Отмечаешь источники и поля — по каждому
   источнику вертикальный список чекбоксов, **ключевой показатель в нём наравне с остальными**
   (помечен «ключ»). Список показателей источника **сворачивается** (кнопка `+`/`−` слева
   от имени; по умолчанию свёрнут, в шапке видно `показателей: N из M`) — при десятке
   источников по сотне полей страница не разъезжается по высоте. Задаёшь срез `as_of`
   (дата или дата-время в удобном формате — ISO, `DD.MM.YYYY`, с секундами или без,
   пусто = текущий момент; распознаётся тем же парсером, что и тип «дата» у сущностей,
   см. ниже; хранится и передаётся в `ds get` как unix-время), настраиваешь
   межисточниковый JOIN (`left.field = right.field`, тип — left/right/inner/full),
   задаёшь имя пресета.
   **Сущности (столбцы таблицы)** — на основе выбранных полей строишь итоговые столбцы
   (весь блок сворачивается кнопкой `+`/`−` у заголовка). Карточка сущности: первая строка —
   **Наименование** и группа пиктограмм справа (`↑`/`↓` порядок, `✕` удалить); ниже
   по строке с подписью — **Способ расчёта** (*поле как есть* / *разрешение коллизии*
   (несколько полей = «то же понятие», победитель по весам доверия, при равных весах —
   по порядку входов) / *производная*
   (`сумма`/`среднее`/`минимум`/`максимум`/`склейка`/`первое непустое`/`кол-во непустых`)),
   **Тип данных** (`текст`/`число`/`дата`/`логич.` — задаёт парсинг; непарсибельное
   показывается сырым текстом с подсветкой). Для `дата` вход `auto` понимает ISO,
   `DD.MM.YYYY`, unix-время и **серийную дату Excel** (5–7 цифр — как выгружает Excel);
   можно задать `excel` явно или свой токенный шаблон. **Источник расчёта** (поле / входы коллизии
   с весами / входы производной). Формат столбца (ширина, выравнивание, кегль) —
   значения по умолчанию, в карточке не настраивается.
   Порядок строк = порядок столбцов. Всё в пресете.
   **Условия** (`+ условие`) —
   строки «поле · оператор · значение», добавляются по одной, любое количество или ни одной;
   применяются по порядку (И) при построении, чтобы сузить массив ещё до страницы «Таблица».
   Операторы: `содержит` / `не содержит` / `равно` / `не равно` / `в списке` / `не в списке` /
   `начинается с` / `заканчивается на` / числовые `> ≥ < ≤` / `пусто` / `не пусто`. Для
   `в списке` / `не в списке` значение — список (одно на строку или через запятую); его можно
   **вставить из буфера обмена** кнопкой рядом с полем (или вручную `Ctrl+V`) — удобно, когда
   есть готовый список идентификаторов. Всё сохраняется в пресете.
   Кнопки: применить и открыть таблицу, скачать пресет (отдельным файлом), загрузить пресет,
   сбросить к базовому; «← К таблице» — вернуться без пересборки. Любое изменение
   автоматически сохраняется в `localStorage` как пресет по умолчанию (best-effort).

Развитие — постепенное. Семантический показатель (расчёт из нескольких источников / вывод по
весам доверия) — позже, это уровень выше файлового контракта.

## Контракт с `ds`

`ds get --preset <preset.json>` генерит по файлу на источник + манифест. Формат — в
[`docs/contract.md`](docs/contract.md). Кратко:

```
data/
├── manifest.js      window.DS_MANIFEST — список источников, их колонки, свежесть, лаг от БД
├── CRM.js           window.DS.sources["CRM"] = { meta:{...}, data:[ {id, <lb>...}, ... ] }
└── ERP.js
```

- широкая таблица: строка на `id`, колонки — выбранные показатели;
- `null` = удалённое значение (`DELETE`), отсутствующий ключ = значения никогда не было;
- каждый источник обновляется независимо → у файлов разные `as_of` / `generated_at`,
  страница показывает свежесть по каждому источнику отдельно.

`data/` — вывод `ds` / поллера, в репозиторий не коммитится (см. `.gitignore`).
Для разработки есть [`sample-data/`](sample-data/) — настоящий вывод `ds get` из двух
источников (генерится [`tools/gen_sample.py`](tools/gen_sample.py)); в наборе намеренно один
свежий источник и один устаревший.

**Пресет по умолчанию** — тоже данные, не код: `base.js` рядом с манифестом, того же
формата (`window.DS_BASE_PRESET = {...}`), грузится той же инъекцией `<script>`.
`sample-data/base.js` коммитится (есть всегда); `data/base.js` — опционален, кладётся
пользователем или поллером рядом со своими данными и переживает обновление кода
`ds-webui`, как и сам `data/`. Если `data/` есть, а `data/base.js` — нет, подставляется
**пустой** пресет, а не пресет из `sample-data/` (он про поля CRM/ERP, которых в чужих
данных может не быть).

## Файлы

Приложение разбито на модули, каждый — свой `<script>` в `index.html`, порядок важен
(зависимости грузятся раньше зависимых). Функциональный стиль сохранён: чистые функции
для трансформации данных отдельно от DOM-рендера и эффектов.

| Файл | Что | Зависит от |
|---|---|---|
| `index.html` | оболочка + bootstrap (загрузка манифеста `data/` → `sample-data/`) | — |
| `util.js` | мелкие функциональные утилиты, hyperscript (`el`/`clear`) | — |
| `effects.js` | загрузка файла источника, скачивание, буфер обмена, `localStorage` | — |
| `dataset.js` | JOIN источников (left/right/inner/full), условия выборки, расширенный/быстрые фильтры, сортировка | `util` |
| `entities.js` | сущности: типизация, парсинг чисел/дат/bool, резолюция коллизий | — |
| `export.js` | выгрузка в CSV / SpreadsheetML (Excel), имя файла | — |
| `store.js` | store (reducer/dispatch/subscribe), нормализация и (де)сериализация пресета | `util`, `dataset`, `entities`, `effects` |
| `view-common.js` | общие DOM-контролы условия, шапка навигации | `util`, `effects`, `dataset` |
| `view-build.js` | страница «Конструктор выборки» | `util`, `store`, `entities`, `dataset`, `view-common` |
| `view-table.js` | страница «Таблица» (грид, фильтры, группировка) | `util`, `dataset`, `entities`, `view-common`, `store` |
| `main.js` | `buildDataset`, экспорт-триггеры, монтаж и рендер-цикл, bootstrap; грузится последним | всё |
| `styles.css` | стили (light/dark) | — |
| `docs/contract.md` | файловый контракт `ds` → `ds-webui`, формат `base.js` | — |
| `tools/gen_sample.py` | регенерация `sample-data/` из настоящего `ds get` | — |
| `scripts/` | макросы офисного пакета: выгрузка листа (или только правок) в JSON для `ds-loader` — см. [`scripts/README.md`](scripts/README.md) | — |
| `tests/` | тесты чистых функций на `node:test` (без браузера, без зависимостей) | — |

`view-build.js`/`view-table.js` дополнительно обращаются к `window.DS_APP.store` /
`.buildDataset` / `.exportXls` / `.exportCsv` (публикуются `main.js`) — лениво, в момент
клика, а не при загрузке скрипта, поэтому обратная зависимость на файл, который грузится
позже, безопасна.

## Разработка

Тесты покрывают чистые модули (`dataset.js`, `entities.js`, `export.js`, `store.js`) —
парсинг чисел/дат, JOIN, условия выборки, резолюция коллизий, выгрузка в CSV/Excel,
нормализация пресета, редьюсер. DOM-модули (`view-*.js`, `main.js`, `effects.js`)
не покрыты — им нужен браузер/jsdom. Требуется только Node.js (`>= 18`, есть встроенный
`node:test`), без npm-зависимостей:

```bash
./run_tests.sh   # или: node --test
```

Отдельно, вручную (не часть `./run_tests.sh`) — [`tests/smoke/dom-smoke.js`](tests/smoke/README.md):
самодельный DOM-стаб без jsdom, реально прогоняющий bootstrap `index.html` +
настоящий `sample-data/` через все `<script>` по порядку — ловит ошибки склейки
модулей (забытый экспорт, не тот порядок, сломанная ленивая ссылка), которые
тесты на чистые функции не видят.

```bash
node tests/smoke/dom-smoke.js
```

Минимальный каркас, покрытие будет расширяться. Каждый модуль экспортирует свои функции
через `module.exports`, если `module` определён (Node), иначе мержит их в общий
`window.DS_APP` (браузер) — в браузере ветка `module.exports` не заходит, поведение не
меняется.

## Статус

Рабочая первая версия: обе страницы, JOIN, фильтры, группировка, экспорт, пресеты.
Не реализовано: drag-and-drop пресета, вычисляемые/семантические показатели, поллер
(отдельный проект).
